## 二、后端接口详细文档

### 基础信息

| 项目 | 说明 |
|------|------|
| 技术栈 | **Flask** + **JSON 文件存储**（轻量级，无需数据库） |
| 协议 | HTTP |
| 数据格式 | JSON (`Content-Type: application/json`) |
| 统一返回格式 | `{ "code": 0, "message": "提示信息", "data": {...} }` |
| 认证方式 | **UUID Token**（放在请求头 `Authorization` 中） |
| 默认后端地址 | `http://localhost:3000` |

### 状态码规范

| code | 含义 |
|------|------|
| 0 | 成功 |
| 1001 | 账号或密码错误 |
| 1002 | 认领失败（个人额度不足） |
| 1003 | 认领失败（账单剩余额度不足） |
| 1004 | 用户名已存在 |
| 1005 | 不允许的操作（如删除自己） |
| 401 | 未登录 / Token 失效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |

> **注意**: 实际后端使用简单 Token（UUID）而非 JWT，Token 不设过期时间，重启服务后所有 Token 失效需重新登录。

### 接口1：用户登录

**请求**

```
POST /api/auth/login
Content-Type: application/json
```

```json
{
    "username": "chaibingkun",
    "password": "cbk4679585858"
}
```

**响应（成功）**

```json
{
    "code": 0,
    "message": "登录成功",
    "data": {
        "token": "a1b2c3d4-...",
        "user_id": 1,
        "username": "chaibingkun",
        "name": "柴炳坤",
        "role": "father",
        "is_admin": true,
        "max_commitment": 500
    }
}
```

**响应（失败）**

```json
{
    "code": 1001,
    "message": "账号或密码错误",
    "data": null
}
```

**字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| token | string | UUID 令牌，后续请求需在 Header 携带 |
| user_id | int | 用户ID |
| username | string | 登录账号 |
| name | string | 显示名称 |
| role | string | 角色：father / mother / son / daughter |
| is_admin | bool | 是否管理员 |
| max_commitment | float | 承诺最大报销金额 |

> **预设账号**：
> - `chaibingkun` / `cbk4679585858`（管理员账号，仅用于后台登录管理，不参与家庭成员记账）
> - `aaa` / `123456`（妈妈，额度300）
> - `son` / `123456`（儿子，额度100）
> - `daughter` / `123456`（女儿，额度80）

### 接口6：认领报销

**请求**

```
POST /api/claims
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
    "bill_id": 1,
    "claimant_id": 2,
    "amount": 30
}
```

**校验逻辑（后端实现）：**
1. ✅ 账单是否存在
2. ✅ 已认领总额 + 本次认领额 <= 账单总金额
3. ✅ 该用户已认领总额 + 本次认领额 <= 该用户承诺总额

**响应（成功）**

```json
{
    "code": 0,
    "message": "认领成功",
    "data": {
        "bill_status": "claiming",
        "remaining": 0
    }
}
```

**响应（失败 - 个人额度不足）**

```json
{
    "code": 1002,
    "message": "认领失败：您的剩余额度不足（剩余 10 元）"
}
```

**响应（失败 - 账单余额不足）**

```json
{
    "code": 1003,
    "message": "认领失败：该账单剩余额度不足（剩余 10 元）"
}
```

```json
    "data": {
        "payable": [

                "bill_id": 1,
                "bill_title": "超市采购",
                "receiver_name": "柴炳坤",
                "amount": 30,
                "payer_confirmed": false,
                "receiver_confirmed": false
            }
        ],
        "receivable": [

                "claim_id": 3,

                "amount": 80,
                "payer_confirmed": true,
                "receiver_confirmed": false

```

| 字段 | 说明 |
|------|------|

| receivable[] | 该用户应收取的（该用户是购买人） |

### 接口8：付款方确认转账

**请求**

```
PUT /api/claims/{claimId}/confirm-payer
Authorization: Bearer {token}
```

**响应**

```json
{
    "code": 0,
    "message": "已确认转账",
    "data": null
}
```

**自动行为**：当 `payer_confirmed` 和 `receiver_confirmed` 都为 `true` 时，该认领记录状态自动变为 `settled`。若账单下所有认领记录都已 `settled`，账单状态自动变为 `settled`。

### 接口15~19：账号管理 CRUD（额外接口）

以下接口服务于 `account-manager.html` 账号管理页面，是文档规划外的附加接口。

#### 15. 获取所有账号（简化版）

```
GET /api/admin/users
Authorization: Bearer {token}
```

返回所有用户的基本信息（不含 used/remain 等统计）。

#### 16. 创建新账号

```
POST /api/admin/users
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
    "username": "newuser",
    "password": "123456",
    "name": "新成员",
    "role": "son",
    "is_admin": false,
    "max_commitment": 100
}
```

#### 17. 修改账号信息

```
PUT /api/admin/users/{userId}
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
    "name": "新名字",
    "role": "daughter",
    "is_admin": true,
    "max_commitment": 200,
    "password": "newpass"
}
```

#### 18. 删除账号

```
DELETE /api/admin/users/{userId}
Authorization: Bearer {token}
```

> ⚠️ 不能删除 `user_id = 1`（初始管理员账号）。

#### 19. 静态文件服务

```
GET /          → 返回 frontend/index.html
GET /{path}    → 返回 frontend/ 下的静态文件
```

Flask 后端同时作为静态文件服务器，提供前端页面和后端管理页面。

| 路径 | 说明 |
|------|------|
| `/` | 前端主应用 `frontend/index.html` |
| `/admin/accounts` | 后端账号管理 `backend/account-manager.html` |
| `/{path}` | `frontend/` 下的其他静态文件 |

## 三、后端实现说明（当前：Flask + JSON）

### 技术选型

| 项目 | 实际方案 |
|------|----------|
| Web 框架 | **Flask 3.x** |
| 数据存储 | **JSON 文件**（`backend/*.json`） |
| 认证方式 | **UUID Token**（服务重启后失效） |
| 跨域 | `flask-cors`，允许所有来源 |
| 密码 | **明文存储**（演示项目，生产环境建议加密） |

### 核心文件

| 文件 | 说明 |
|------|------|
| `backend/app.py` | **单文件实现全部 19 个接口**，约 600 行 |
| `backend/requirements.txt` | 仅依赖 `flask` + `flask-cors` |
| `backend/users.json` | 用户数据，首次启动自动生成预设账号 |
| `backend/bills.json` | 账单数据，初始为空 |
| `backend/claims.json` | 认领记录数据，初始为空 |

### 与原始设计文档的差异

| 原始设计（接口文档旧版） | 实际实现（app.py） |
|---|---|
| FastAPI + SQLAlchemy + MySQL | Flask + JSON 文件存储 |
| JWT Bearer Token | UUID 简单 Token |
| bcrypt 密码加密 | 明文密码 |
| 模块化 routers/ 目录 | 单文件 app.py |
| 14 个接口 | 19 个接口（含账号管理 CRUD） |

## 四、如何部署

### 方式一：本地运行（开发）

```bash
# 1. 进入后端目录
cd backend

# 2. 安装依赖
pip install -r requirements.txt

# 3. 启动服务
python app.py

# 4. 打开浏览器访问
# http://localhost:3000
```

### 方式二：前端独立部署（仅页面）

```bash
# 直接用浏览器打开 frontend/index.html
# 此时 USE_MOCK = true，使用演示数据，无需后端
```

### 对接说明

1. 修改 `frontend/index.html` 中将 `USE_MOCK` 改为 `false`
2. 默认后端地址 `http://localhost:3000`，如需修改调整 `API_BASE` 变量
3. 确保后端服务已启动
4. 打开前端页面，使用预设账号登录
